# Автоматизація документообігу заступника директора з академічних питань

Десктопний застосунок (Python + CustomTkinter + PostgreSQL) для:
- імпорту списків студентів із наказів про зарахування (.doc/.docx);
- розпізнавання наказів про нагородження/подяки та нарахування балів;
- розпізнавання наказів про догани: −0.5 бала, якщо в рейтингу вже є бали, і 0 якщо балів немає;
- ведення рейтингової системи студентів з історією нарахувань.

## Архітектура

```
app.py                 — головне вікно, вкладки, діалоги налаштувань
config.py              — завантаження/збереження налаштувань (БД, рівні балів)
database.py            — шар доступу до PostgreSQL (нормалізована схема)
matching.py            — зіставлення студента з наказу зі студентом у БД
export.py              — експорт рейтингу/списку групи в .xlsx
parsers/students_parser.py — парсинг списків студентів з .docx
parsers/reward_parser.py   — парсинг наказів про нагородження з .docx
tests/                 — модульні тести для парсингу та зіставлення
```

### Схема бази даних

```
groups (id, name, study_year, curator)
students (id, full_name, group_id → groups.id, funding, note)
orders (id, order_number, order_date, event_title, level_type, default_points)
achievements (id, student_id → students.id, order_id → orders.id, points_awarded)
```

Одна таблиця `students` з `group_id` — замість окремої SQL-таблиці на
кожну групу, як було раніше. Рейтинг рахується одним запитом з
`JOIN` + `GROUP BY`, а не циклом по десятках таблиць.

## Встановлення

```bash
pip install -r requirements.txt
python app.py
```

При першому запуску відкрийте **⚙ Налаштування** й вкажіть параметри
підключення до PostgreSQL. Пароль зберігається локально у
`~/.doc_flow_app_config.json` — для спільного комп'ютера краще не
зберігати пароль і вводити його щоразу.

## Тестування

```bash
python -m unittest discover -s tests -v
```

## Збірка .exe (Windows)

На комп'ютері з Python запустіть `build_exe.bat`. Після збірки з'явиться
`dist\DocFlow.exe` — його можна скопіювати й відкрити без встановлення Python.
PostgreSQL усе одно має бути доступний (локально або в мережі) — параметри
підключення задаються в **Налаштування**.

## Відомі обмеження та напрямки подальшого розвитку BUH buh buh

- **Зіставлення імен** використовує коефіцієнт подібності рядків
  (`difflib`), а не морфологічний аналізатор — прізвища у непрямих
  відмінках (давальний, родовий) розпізнаються гірше, ніж у називному.
  Покращення: підключити лематизатор (напр. `pymorphy2`/`pymorphy3`
  для укр./рос. морфології).
- **Пароль до БД** зберігається у відкритому JSON-файлі профілю
  користувача. Для продакшн-використання варто перенести зберігання
  в системне сховище паролів (модуль `keyring`) або вимагати введення
  пароля щоразу.
- **Формат .doc** читається лише на Windows через MS Word (`pywin32`).
  На інших ОС файл потрібно попередньо зберегти як `.docx`.
- **Права доступу**: застосунок наразі не розрізняє ролі користувачів
  (перегляд/редагування/повне очищення бази доступні всім однаково).
  Якщо застосунком користуватимуться кілька співробітників —
  варто додати автентифікацію та рольову модель.
- Парсинг списків і наказів побудований на регулярних виразах під
  типовий формат таблиць деканату; суттєво інша структура документа
  (інші заголовки колонок, інший порядок ПІБ) може вимагати коригування
  списку стоп-фраз/шаблонів у налаштуваннях.
